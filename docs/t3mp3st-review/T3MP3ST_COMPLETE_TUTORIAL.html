1 · T3MP3ST in 5 minutes

T3MP3ST ("TEMPEST" — Tactical Execution Multi-agent Platform for Elite Security Testing) is a single Node.js/TypeScript application that orchestrates LLM-driven, evidence-disciplined security testing against authorized targets. package.json:1-3

The ten things to know

  1. What it is: one modular TypeScript monolith, run as an HTTP server, a CLI, or an MCP server — all wrapping the same engine. src/server.ts, src/cli.ts, src/mcp-server.ts
  2. Components: an Express backend + a hand-authored browser SPA ("War Room") + an execution engine (TempestCommand) that drives Admiral (intake), Op General (planner), and the Arsenal (tools). src/index.ts, docs/index.html
  3. How they talk: the SPA calls the backend over HTTP JSON at http://127.0.0.1:3333. There is no separate frontend server — the backend serves the UI as a static file. src/server.ts:7950-7952
  4. Where the UI lives: docs/index.html, served at /ui (root / redirects there). src/server.ts:7950-7952
  5. Where the API lives: ~129 routes under /api/* in src/server.ts.
  6. Where state is stored: in-memory by default (lost on restart). Set T3MP3ST_STATE_DIR to persist to state.json + events.jsonl. src/server.ts:926-939
  7. How you launch it: npm run server (dev) or npm run build then npm run server:prod (prod). package.json:24-25
  8. How a hunt flows: intake (Admiral) → plan (Op General) → gate check → approval receipt → execution → evidence.
  9. How approvals work: live actions require a per-action:target "receipt" (an ApprovalRequest). Missing → HTTP 403; you approve on the Scope Receipts page. src/server.ts:1319-1332, 5027
  10. Where results appear: the War Room's Findings, Evidence Vault, Work Order Board, and Scope Receipts pages.

End-to-end flow (as-built)

The #1 naming trap
The War Room's "⭐ Op Admiral" page drives the Op General (/api/general/*) — it is not the Admiral module. The Admiral is the separate chat-intake wizard ("⚓ Guided"). Keep them distinct. docs/index.html nav; src/general/index.ts; src/admiral/index.ts

6 · State persistence (T3MP3ST_STATE_DIR)

Default = no persistence
With T3MP3ST_STATE_DIR unset, stateRoot() returns the literal string 'memory' and every mission, approval, receipt, and piece of evidence is lost on restart. Set it for any real engagement. src/server.ts:926-929
QuestionAnswer (verified)
What does it control?The root directory for persisted server state. src/server.ts:926
What files are stored?state.json (all ledgers) and events.jsonl (event log). src/server.ts:931-939
When created?On the first debounced write (1000 ms after a state change). src/server.ts:1127-1143
What survives restart?All 11 ledgers — missions, approvals, evidence, findings, hypotheses, work orders, etc. — reloaded at boot by loadPersistedState(). src/server.ts:1164-1187
What is ephemeral?Everything, if the dir is unset. Also the tool-tier ApprovalController state is process-lifetime only (never persisted).
Can two instances share it?Not recommended. Writes are last-writer-wins snapshots of in-memory Maps; two servers would clobber each other. IMPLEMENTED
Auto-created if missing?Writes create the file; ensure the parent directory is writable. Reads are silent on ENOENT (treated as first run). src/server.ts:1164-1187
What if deleted?Next boot starts empty (fresh state); a running server keeps its in-memory copy until the next write recreates the file.

Persistent config
To make it permanent, add the export line to your shell profile (~/.zshrc / ~/.bashrc) or the Docker Compose environment: block. Do not put secret keys on the command line where they land in shell history — prefer a .env file (Part 9) or the setup wizard's stored config.

Backup / move

Because state is a plain state.json, backing up = copying that file. See Part 23 for the safe (stop-first) procedure. Moving = point T3MP3ST_STATE_DIR at a new path and copy state.json/events.jsonl there while the server is stopped.

7 · T3MP3ST_HOST / network binding

This is a command-executing local API
The backend can run tools and subprocesses. It has no built-in authentication — its safety model is "loopback only." Exposing it to a network without a real auth layer in front hands remote parties a command-execution surface. src/server.ts:144-158 (security comment)
AspectValue (verified)
VariableT3MP3ST_HOST
Default127.0.0.1 — or 0.0.0.0 when DOCKER=true
FormatAn IP/hostname string passed to app.listen(PORT, HOST). IPv4 (127.0.0.1, 0.0.0.0) and IPv6 (::1) are recognized by the loopback test
Loopback detectionRegex /^(127\.|localhost$|::1$|\[::1\]$)/i decides HOST_IS_LOOPBACK
Host-header guardThe Host-header allowlist is enforced only when bound to loopback. Explicitly binding to a non-loopback address disables that guard (you've opted into network exposure)

src/server.ts:152, 158, and the CORS/origin-guard block that follows

127.0.0.1 → reachable only from this machine ✅ SAFE DEFAULT Host-header allowlist ACTIVE (anti-CSRF / DNS-rebind) 0.0.0.0 → reachable from the LAN / anywhere routable ⚠️ DANGER Host-header guard DISABLED · no auth · runs commands
Do not expose it
Keep the default loopback bind unless you deliberately front it with authentication (e.g. an authenticated reverse proxy / VPN). The Docker image sets DOCKER=true → binds 0.0.0.0 inside the container, but docker-compose.yml publishes the port as 127.0.0.1:3333:3333, so it stays loopback-only on the host. Dockerfile (ENV DOCKER=true); docker-compose.yml (ports)

9 · Env files & precedence

Verified loader behavior
Config is a Conf JSON store, not a flat .env reader. At startup loadEnvVariables() loads ~/.t3mp3st/.env or ~/.env — deliberately not ./.env in the working directory, to avoid slurping a scanned target's secrets. It only fills keys that are unset; a real exported env var always wins. src/config/index.ts:714-766 (esp. 717-719, 743)

Precedence (highest → lowest)

1. process.env (real exported environment) ← always wins 2. ~/.t3mp3st/.env or ~/.env (home-dir file, fills unset keys only) 3. Conf store (~/.t3mp3st/… written by `npm run setup`) 4. DEFAULT_SETTINGS (hardcoded)

src/config/index.ts:136-226 (defaults), 693-766 (store + env load), 816-859 (key resolution)

Docker is the exception
docker-compose.yml uses env_file: .env, so in the container a project-root .env is loaded (by Compose, not by the app's loader). docker-compose.yml

Safe .env template

Copy .env.example → .env (git-ignored via .dockerignore/.gitignore). Never commit real secrets.

17 · Stopping

Ctrl-C sends SIGINT. The handler calls flushPersist() then process.exit(0). It does not call server.close(), so in-flight HTTP requests may be cut mid-response — a graceful-drain gap, not a data-loss risk (state is flushed first). src/server.ts:8009-8017

State is flushed on the way out
If T3MP3ST_STATE_DIR is set, the shutdown flush writes the latest state.json. If it's unset, there's nothing to flush — everything was in memory and is gone. src/server.ts (flushPersist)

56 · Control-plane security

This is a command-executing API with no authentication
The backend can run tools and subprocesses and has no built-in auth. Its entire safety model is "bind to loopback." Anyone who can reach the port can drive it. src/server.ts:144-158 (security comment)
ControlStateOperator action
Network bindLoopback default; 0.0.0.0 under DOCKER=trueKeep loopback; if exposing, front with authenticated proxy/VPN (Part 7)
Host-header allowlistActive only on loopback bindDon't bind non-loopback without external auth — the guard turns off
Approval gates403 (server) + tool-tier; one weak path (/approve no precondition)Prefer authorize-target; don't rely on re-approve behavior
scope.authorized for local targetsClient-trusted — a client can assert authorization to skip approval for local actionsTreat the client as trusted; don't expose the API. operationAllowsLocalAction
Dangerous flagsT3MP3ST_APPROVED_TOOLS, T3MP3ST_HERMES_YOLO, T3MP3ST_FULL_ARSENALSet only deliberately — they authorize tools / disable gates
Target headersTEMPEST_TARGET_HEADERS carries live tokens; same-origin only, stripped on redirectTreat as a secret; scope to the exact origin
Golden rule
Run it on the operator's own machine, bound to loopback, single-user. Everything else is an explicit risk decision.
